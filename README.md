# LOOMFALL — 夜を織る

**プレイURL：[https://onego15.github.io/survivors-gpt/](https://onego15.github.io/survivors-gpt/)** · [ソースコード](https://github.com/onego15/survivors-gpt)

GitHub Pagesで公開済み。公開先のChromeで起動・操作・経験値回収・強化選択まで検証済み（HTTP 200、JavaScript/アセットエラー0件）。

群れを誘い、糸を描け。そのひと結びが、夜をほどく。

移動の軌跡を閉じて敵を収穫する、オリジナルのアクションローグライト。約12分の夜を、自分だけの能力の組み合わせで越える。

録画は実行中のゲームのDOMとCanvasをChromeから取得したもの。通常のシード12のプレイをQA用操作で終盤まで高速進行させ、録画中は通常速度で移動・結び・能力選択を自動操作している。生命・攻撃力・クールダウンの特別な変更は行っていない。架空の映像、生成したプレイ映像ではない。録画設定と開始・終了状態は [recording.json](docs/recording.json) に保存。

## このゲームの発想

Vampire Survivorsの「移動に集中できる操作」「危険と報酬の選択」「シナジーで群れを圧倒する成長」を、**陣取り・領域を閉じる遊び**と統合した。

歩くと糸が残る。SPACEで現在位置と始点をつなぐと、内側と縁の敵をまとめて攻撃し、経験値も回収する。大きな輪ほど強力だが、敵の中を回り込む危険がある。3体以上を倒した結びは生命を回復。糸の減速で群れを溜め、自動針で道を開き、結ぶ時点を選ぶ。独自の仕組みが、移動・戦闘・成長を一つの循環にしている。

狭すぎる輪は近距離の衝撃波になる。きれいな一周を走り切る必要はなく、最後の辺はSPACEで結べる。糸の長さには上限があり、古い部分から消える。自己交差した領域は偶奇ルールで判定するため、まずは交差しない大きな弧がおすすめ。

## 特徴・ビルド

- 3種類の開始糸：領域に強い翡翠、自動針に強い朱、領域で足止めする月白。
- 16種類の強化を3択で選択。2回の引き直し。最終盤まで全能力を取り切れず、選択の差が残る。
- 雷の連鎖収穫、貫通針と毒の伝播、霜と持続領域と結晶針などの相互作用。
- 4種類の通常敵と、3:30・7:00・11:00に登場する3体の守護者。最後の守護者を倒すとエンディング。
- 永続する記憶の欠片で、生命・移動・経験値を小幅に強化。初回からすべての開始糸を使える。
- システムフォント、オリジナルのCanvasアート、Web Audioの生成BGMと効果音。外部CDNやゲームアセットへの依存なし。
- ポーズ、タブ非表示時の自動休止、音量調整、画面揺れ軽減、タッチスティックと操作ボタン。

| 操作 | キー / 入力 |
|---|---|
| 移動 | WASD / 矢印キー / 左のタッチスティック |
| 結ぶ | SPACE / キャンバス左クリック /「結ぶ」|
| すり抜け | SHIFT / 右クリック /「疾走」|
| 強化を選ぶ | カードをクリック / 1・2・3 |
| 休憩・再開 | ESC / P / 右上のⅡ |

ゲームパッド操作は未実装。マウスクリックは移動先の指定ではなく「結ぶ」操作。保存はこのブラウザのlocalStorageに行い、プライベートモードなどでは保持されない場合がある。

## ローカル起動と公開

Node.js 20以降。ゲーム本体は依存パッケージなし。

```sh
npm start
```

[http://localhost:5187/](http://localhost:5187/) を開く。

```sh
npm test
npm run check
npm run build
```

`dist/` が静的サイト一式。画像・CSS・ES Modulesはすべて相対URLなので、`/survivors-gpt/` のようなサブパスに対応する。

GitHub Pagesは main ブランチの `/ (root)` から配信。`.nojekyll` を含むビルド不要の静的サイトとして公開する。GitHub認証トークンに `workflow` スコープがないため、Actionsによる公開は使用していない。Actions用テンプレートは [docs/pages-workflow.yml](docs/pages-workflow.yml) に保存。必要な権限がある環境では `.github/workflows/pages.yml` に配置し、Settings → Pages → Source を GitHub Actions に設定してmainへpushすると、テスト・ビルド・公開を自動化できる。

## テストと改善

シミュレーションと実ブラウザによる検証記録。

- `npm test`：11 / 11 合格（エンジン8項目＋異なる3ビルドでの開始からクリアまでの通しテスト）。エンジンテスト：領域判定、自己交差、経験値吸引、狭い輪、無入力ダッシュ、境界、不正な能力選択、全能力併用、敗北・リトライ、ボス撃破、乱数の再現性。
- 通しシミュレーション：無敵化なし・能力の後付けなし。領域 / 針 / 庭の3戦略、各3シード、計9回中7回クリア。針特化は1/3、領域と庭はそれぞれ3/3。これは限られた自動操作方針での結果で、一般プレイヤーの勝率ではない。詳細は [balance.json](docs/balance.json)。
- ブラウザ操作：タイトル、遊び方、移動、領域生成、SPACE、ポーズ、レベルアップ3択、数字キー、390×844表示、タッチの結び。エラー0件。[browser-qa.json](docs/browser-qa.json)
- 公開先の実操作（survivors-gpt）：HTTP 200、全アセット正常。00:11まで進行し、17体撃破・3回の結び・Lv.2到達・強化選択1回を確認。ポーズ、再開、記憶の織機、公開先でのQA API無効化も検証。[public-qa.json](docs/public-qa.json)
- 終盤性能（録画停止、headless Chrome / 1200×800）：フレーム中央値16.2ms、平均21.7ms。描画平均3.78ms、シミュレーション平均1.32ms。205体前後の敵がいる6秒間の測定で、実機全般を保証するものではない。[performance.json](docs/performance.json)
- 実ブラウザの終盤：通常プレイから最終ボス、エンディング、再挑戦、敗北画面まで確認。[ending-qa.json](docs/ending-qa.json)
- 初期実装後、自動攻撃への偏り、経験値回収、全ビルドの同一化、針構成の弱さ、背景の視認性、終盤負荷を改善。具体的な変更は [DESIGN.md](docs/DESIGN.md)。

再現方法：`npm test`、`node tools/balance.mjs`。追加のブラウザQAにはPlaywrightとChrome、録画エンコードにはPythonのPillowとimageio-ffmpegが必要。`node tools/browser-qa.mjs`、`node tools/record.mjs`、`python tools/make-demo.py`。ブラウザQAは起動済みのポート5187へ接続する。

QA操作APIは `localhost` / `127.0.0.1` の `?test=1` に限定。公開サイトでは有効にならない。録画・負荷検証時は自動操作を使った。手動による長時間の外部プレイテストは未実施。

## 既知の問題・今後の余地

- 本作品は約12分の1つの庭園に集中。ステージ選択、クラウド保存、オンラインランキングはない。
- タッチUIは実装・Chromeで検証したが、iOS Safari実機、幅広いモバイルGPU、Firefoxでの検証は未実施。
- 非常に小さい画面では強化カードの説明が小さい。横画面推奨。
- 終盤は敵240体、粒子650個などの上限で負荷を制御。低性能端末ではさらに重くなる可能性がある。ゲームはフレームの遅延を最大50msに制限し、タブ復帰時に瞬間的に進めない。
- Web Audioは最初の操作後に開始。音の出力・音色の主観的な聴感は、実機での人間による比較評価を行っていない。
- 針特化の自動操作は他の構成より難しい。敵弾の回避・結びによる回復の確保が重要。
- 守護者が生存中は12:00を超えても戦闘を継続。最後の守護者の撃破がクリア条件。
- セーブのエクスポート・インポートは未実装。ブラウザのサイトデータ削除で記録は失われる。
